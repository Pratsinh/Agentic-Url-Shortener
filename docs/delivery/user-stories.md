# User stories and acceptance criteria

**Requirement:** "Build a URL shortener with create, redirect, expiry, click analytics, an audit trail, error handling and logging, Cassandra storage with a Redis cache, a published OpenAPI contract and a governed tool gateway for agents, delivered by governed AI agents"

Generated by `RequirementsAgent` from the product story catalog. Acceptance-criterion ids are referenced by tests through `@Verifies` and traced by the QA agent.

## US-1 Shorten a URL

**As a** link creator, **I want** to turn a long URL into a short code, **so that** I can share a compact link.

| AC | Given | When | Then |
|---|---|---|---|
| AC-1.1 | a valid public http(s) URL | I POST it to /api/v1/links | I get 201 with a code, the short URL and a Location header |
| AC-1.2 | a missing, malformed, non-http(s) or credential-bearing URL | I submit it | I get 400 and nothing is stored |
| AC-1.3 | a URL whose host is loopback, private, link-local or an obfuscated IP | I submit it | I get 400 (SSRF guard) |
| AC-1.4 | a TTL that is zero, negative or longer than 365 days | I submit it | I get 400 |
| AC-1.5 | every generated code collides | the service has retried 5 times | I get 503 instead of an overwritten link |

## US-2 Redirect

**As a** visitor, **I want** a short link to take me to the original URL, **so that** short links work like the long ones.

| AC | Given | When | Then |
|---|---|---|---|
| AC-2.1 | an existing, unexpired code | I GET /{code} | I get 302 to the original URL |
| AC-2.2 | an unknown or malformed code | I GET it | I get 404 |
| AC-2.3 | a redirect request | it succeeds or fails | only successful redirects increment the click count |

## US-3 Link expiry

**As a** link creator, **I want** links to stop working after a TTL, **so that** temporary links do not live forever.

| AC | Given | When | Then |
|---|---|---|---|
| AC-3.1 | a link with a TTL | the TTL has elapsed (boundary inclusive) | redirect returns 410 |
| AC-3.2 | a link without a TTL | any amount of time passes | it still redirects |

## US-4 Click analytics

**As a** link owner, **I want** to see how often my link was used, **so that** I can measure reach.

| AC | Given | When | Then |
|---|---|---|---|
| AC-4.1 | a link that was clicked | I GET /api/v1/links/{code}/stats | I see the URL, total clicks, created/expiry time and last access |
| AC-4.2 | an expired link | I request its stats | they are still returned |
| AC-4.3 | thousands of concurrent redirects | they complete | every click is counted exactly once |

## US-5 Audit trail

**As a** operator, **I want** a record of every create and redirect, **so that** I can investigate abuse and incidents.

| AC | Given | When | Then |
|---|---|---|---|
| AC-5.1 | any create or redirect | it succeeds or is rejected | an audit event records the outcome |
| AC-5.2 | a URL with a query string | it is audited or logged | only its host is recorded |
| AC-5.3 | an existing link | I GET /api/v1/links/{code}/audit | I see its history; unknown codes return 404 |
| AC-5.4 | the audit capacity is reached | new events arrive | the oldest events are evicted |

## US-6 Errors and observability

**As a** API client and operator, **I want** consistent errors and traceable logs, **so that** failures are diagnosable without leaking internals.

| AC | Given | When | Then |
|---|---|---|---|
| AC-6.1 | any rejected request | the API responds | the body is an RFC 7807 problem |
| AC-6.2 | a malformed or missing JSON body | I POST it | I get a 400 problem |
| AC-6.3 | an unexpected server failure | the API responds | I get a 500 problem with a reference id and no stack trace |
| AC-6.4 | any request | it is processed | the response carries X-Request-Id (a safe incoming id is reused, others replaced) |
| AC-6.5 | a code containing newlines or control characters | it is logged or audited | it is neutralised so log lines cannot be forged |

## US-7 Governed agent workflow

**As a** engineering lead, **I want** agents to work inside explicit guardrails, **so that** autonomy never bypasses review.

| AC | Given | When | Then |
|---|---|---|---|
| AC-7.1 | a stage graph | the run executes | stages respect dependencies and independent stages overlap |
| AC-7.2 | an agent that fails | attempts remain | it is retried within the bound, then its fallback runs |
| AC-7.3 | a HIGH-impact stage | its agent finishes | outputs commit only after human approval; rejection or timeout blocks them |
| AC-7.4 | a CRITICAL policy violation | it is detected | the run safe-stops without retrying |
| AC-7.5 | a stage failing with ROLLBACK_RUN | earlier stages succeeded | they are compensated in reverse order |
| AC-7.6 | the audit log | any event is altered | verification detects the tampering |

## US-9 Durable storage and caching

**As a** operator, **I want** links stored in Cassandra and redirects served from a Redis cache, **so that** links survive restarts and hot links stay fast.

| AC | Given | When | Then |
|---|---|---|---|
| AC-9.1 | a link created with Cassandra storage | the service restarts | the link still resolves |
| AC-9.2 | two concurrent creates with the same code | both reach Cassandra | exactly one is stored (lightweight transaction) and the other is retried |
| AC-9.3 | a cached link | it is resolved again | it is served from Redis without reading Cassandra |
| AC-9.4 | a link with a TTL | it is cached | the cache entry expires no later than the link (max 24 h) |
| AC-9.5 | an unknown code | it is requested repeatedly | only the first request reaches Cassandra for 60 s |
| AC-9.6 | Redis is unavailable | a link is created or resolved | requests read through to Cassandra and still succeed |

## US-10 Published API contract

**As a** API client (including the orchestrator), **I want** the shortener's API published as an OpenAPI contract that the service provably implements, **so that** clients are generated from the contract and never depend on the service's code.

| AC | Given | When | Then |
|---|---|---|---|
| AC-10.1 | the running service | I GET /api/v1/openapi.yaml | I get the OpenAPI contract it implements |
| AC-10.2 | the contract and the controllers | the build runs | every documented operation is implemented and every endpoint is documented |
| AC-10.3 | a create, redirect, stats and audit flow | the responses are checked against the contract | every field is documented and every required field is present |

## US-11 Governed tool access

**As a** engineering lead, **I want** agents to reach external systems only through a governed tool gateway, **so that** an LLM can use real APIs without ever bypassing permissions, policies or human approval.

| AC | Given | When | Then |
|---|---|---|---|
| AC-11.1 | a proposed tool call | the tool is unknown, not granted to the stage, or its arguments do not fit its spec | it is denied without being executed and the denial is audited |
| AC-11.2 | a MUTATING tool call | it is proposed | it runs only after human approval; rejection, timeout or a failing approval channel denies it |
| AC-11.3 | tool arguments or a tool output containing a credential | the call is processed | the call is blocked or the output withheld, and the credential reaches neither the audit log nor the planner |
| AC-11.4 | a transient failure of the target system | a tool call fails | a read-only call is retried within its bound and a mutating call is never retried |
| AC-11.5 | a CRITICAL tool-policy violation or an exhausted call budget | further calls are proposed in the run | they are all denied |
| AC-11.6 | a tool-using agent in a workflow stage | it runs | its planner sees only the granted tools, results are framed as untrusted data, and a planner that never finishes fails the attempt |
| AC-11.7 | the shortener's OpenAPI contract | the shortener tools are built and called | names, parameters and risk come from the contract and every call carries its correlation id as X-Request-Id |
| AC-11.8 | a WORKSPACE_WRITE tool call | it is proposed | it needs no per-call approval, is never retried, and policies see the calling run and stage (least privilege) |
