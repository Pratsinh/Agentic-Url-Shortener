# Requirement analysis: Link preview endpoint: GET /api/v1/links/{code}/preview (side-effect free)

**Classification:** BROWNFIELD

**Engineering problem:** Add a read-only operation to the shortener that, for a known code, returns the link's originalUrl, createdAt, expiresAt (null for a non-expiring link) and a boolean `expired`, computed against the service Clock with the existing inclusive boundary (ShortLink.isExpiredAt: now >= expiresAt). The operation must not redirect (no 302/Location), must not call repository.recordClick, and must not write LINK_REDIRECTED/LINK_REDIRECT_REJECTED audit events or otherwise change the stats (totalClicks, lastAccessedAt). Unknown or malformed codes return 404 as an RFC 7807 problem (application/problem+json), via the existing ShortenerException.NotFound -> ApiExceptionHandler path. Unlike redirect, an expired link is not an error: the preview answers 200 with expired=true, as stats already does for expired links. The change touches the hexagonal layers (ShortenerService use case, ShortenerController, a new response DTO) and the OpenAPI contract in shortener-api. ApiContractTest enforces that every controller mapping is documented and the reverse, and checks that response body fields equal the documented schema properties exactly. The generated shortener-client gains a new method automatically. The orchestrator's tool set is a curated list, so the new operation is not exposed as a tool unless asked.

## Acceptance criteria
- **AC-1** GET /api/v1/links/{code}/preview for an existing, unexpired link with a TTL returns 200 application/json with originalUrl equal to the stored URL, createdAt and expiresAt as ISO-8601 instants equal to the stored values, and expired=false. The response has no Location header and is not a 3xx.
- **AC-2** For a link created without a TTL the preview returns 200 with expiresAt=null (the field is present, serialized as null) and expired=false, however much time has passed.
- **AC-3** For an expired link the preview returns 200 (not 410) with expired=true. At exactly t = expiresAt, expired=true (inclusive boundary, consistent with redirect); one millisecond earlier it is false. This is verified with MutableClock.
- **AC-4** Calling preview any number of times, for unexpired and expired links, does not change GET /api/v1/links/{code}/stats: totalClicks stays the same and lastAccessedAt stays null if there was no earlier redirect. A later real redirect still counts exactly one click.
- **AC-5** Preview does not add audit events: GET /api/v1/links/{code}/audit and the recent audit list contain no new entries after a preview, for both success and 404.
- **AC-6** An unknown code (well-formed but not stored) and a malformed code (for example shorter than 4 characters, or containing non-alphanumerics) return 404 with Content-Type application/problem+json and a Problem body (status=404, detail set). No stack trace or internals appear in the body. The response carries X-Request-Id.
- **AC-7** A storage outage during preview surfaces as a 503 problem, not a raw driver error or a 500. This is covered the same way as existing outage handling.
- **AC-8** shortener-v1.yaml documents the path /api/v1/links/{code}/preview with a GET operation. It has a unique operationId (getLinkPreview), tag links, the Code and RequestId parameters, a 200 response with a new LinkPreview schema, and 404, 503 and 500 problem responses. The LinkPreview schema has exactly the properties the service sends (originalUrl, createdAt, expiresAt nullable, expired) and lists the always-present ones as required.
- **AC-9** ApiContractTest passes. Documented and implemented operations are identical, and the preview response of a real created link conforms to the LinkPreview schema through assertConforms, which compares property names and required fields.
- **AC-10** Backward compatibility: the behaviour of POST /api/v1/links, GET /{code}, /stats, /audit and /api/v1/audit and their existing schemas are unchanged. The existing ShortenerToolsTest (curated tool list of 4) and the whole build, including the 99% line/branch and 100% method coverage gate, still pass. The generated client builds with the new operation.
- **AC-11** New tests carry @Verifies tags with ids added to StoryCatalog, and they cover the success, no-TTL, expired, no-side-effect and 404 cases at the service level (ShortenerServiceTest) and at the HTTP level (ShortenerApiTest, ApiContractTest, ApiErrorHandlingTest where appropriate).

## Ambiguities
- **AMB-1**: Should an expired link's preview return 200 with expired=true, or 410 like the redirect?
  - why it matters: It decides the status contract and tests. The requirement asks for 'whether it is expired' as a field, which only makes sense if expired links can be previewed.
  - proposed assumption: 200 with expired=true. 410 is not documented for preview. This matches /stats, which stays available after expiry.
- **AMB-2**: Should a preview be audited (a new AuditEvent action) or logged?
  - why it matters: The AuditEvent.action enum in the contract has four fixed values. Adding one changes a published schema and clients' enums. The requirement says only 'without counting a click'.
  - proposed assumption: No audit event and no contract enum change; only a DEBUG-level log line without the full URL. Preview is a pure read like stats, which is not audited either.
- **AMB-3**: Exact JSON field names and the shape of the response.
  - why it matters: The contract is public and generated clients depend on the names.
  - proposed assumption: Reuse the names from CreateLinkResponse and LinkStats: originalUrl, createdAt, expiresAt (nullable) and a new boolean `expired`. The code is not echoed, since the caller supplied it; add `code` if consistency with LinkStats is preferred. The schema is named LinkPreview and the operationId is getLinkPreview.
- **AMB-4**: Should preview be exposed as an orchestrator tool (ShortenerTools)?
  - why it matters: The curated tool list is asserted in ShortenerToolsTest and README. Adding a tool changes the gateway surface and docs.
  - proposed assumption: Out of scope. The tools list stays at four. The generated client still gets the method.
- **AMB-5**: Does exposing the originalUrl through preview to anyone who knows the code raise a privacy concern?
  - why it matters: The full URL (possibly with tokens in the query string) is deliberately kept out of logs and audit, but the redirect already discloses it to anyone with the code, and stats already returns it.
  - proposed assumption: There is no new exposure, because the same code already reveals the URL through redirect and stats. No authentication is added, since the service has none. The preview never logs or audits the full URL.

# Plan: Add GET /api/v1/links/{code}/preview (no redirect, no click, audited as LINK_PREVIEWED) with OpenAPI contract and tests

## Design
GUIDANCE NOTE: the binding answer to AMB-2 is "yes" (a preview IS audited). That overrides the analysis' proposed assumption and its AC-5 ("no audit events"). This plan therefore revises AC-5: a preview writes audit events (LINK_PREVIEWED / LINK_PREVIEW_REJECTED), but still changes nothing in stats (no recordClick, so totalClicks and lastAccessedAt are untouched) and never redirects. AMB-1: an expired link returns 200 with expired=true. AMB-3/4/5 as approved (no `code` field in the response; no orchestrator tool; no auth).

Domain/app (shortener-service):
- New record domain/LinkPreview(String originalUrl, Instant createdAt, Instant expiresAt, boolean expired), framework-free. It is returned directly by the controller, like LinkStats, so nulls serialize as for the other DTOs.
- AuditEvent.Action gets LINK_PREVIEWED and LINK_PREVIEW_REJECTED appended.
- ShortenerService.preview(code): now = clock.instant(); link = lookup(code) (NotFound for malformed/unknown; StorageUnavailable passes through); expired = link.isExpiredAt(now) (inclusive). Never calls recordClick, never throws Expired. On success: audit LINK_PREVIEWED with detail "host=<host> expired=<bool>" and a DEBUG log. On ShortenerException: audit LINK_PREVIEW_REJECTED (code only if well-formed, else null, as redirect does), INFO log, rethrow. Host only, never the full URL.

Web + contract:
