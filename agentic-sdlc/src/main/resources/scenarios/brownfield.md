Enhance the existing link creation API (POST /api/v1/links) so callers can optionally choose their own short code by sending a "customCode" field. A custom code must follow the existing short-code format (4 to 16 letters or digits); an invalid one is rejected with 400, and a code that is already taken is rejected with 409 Conflict, both as RFC 7807 problems like the other errors. Requests without customCode must behave exactly as they do today (backward compatible: same generated codes, same responses, same audit events). Update the OpenAPI contract and add tests for the new behaviour and for compatibility.
